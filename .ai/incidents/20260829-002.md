## Root Cause

**Primary:** `.vercelignore` at repo root contains `**/dist` pattern (line 6, since `a4b36da` Aug 23). This file **IS git-tracked** (corrected from initial assessment). When Vercel CLI deploys via `vercel deploy --prod --yes`, it reads `.vercelignore` and excludes matching files from upload. The pre-built `dist/` folder (output of `vite build`) is excluded → Vercel receives only `src/` and config files, no output directory → "No Output Directory named 'dist' found" error.

**Secondary:** AI Engineering Team did **NOT** verify Vercel deploy status after push. CI workflow `deploy-frontend.yml` runs `vercel deploy ... --yes` but the team relied on local typecheck/build success as proof of deployment. When Vercel deployment fails, the previous successful deploy is retained as production — but the team did not check this, and falsely reported "deploy successful" to owner.

**Tertiary:** `.github/workflows/deploy-frontend.yml` path filter did NOT include `.vercelignore`. So even after fix `5fa3240`, no Vercel deployment was created (workflow didn't trigger). Fix `bee829f` adds `.vercelignore` to path filter — the workflow file is already in the filter, so this commit triggers itself.

## What Went Wrong

1. **False-positive verification:** AI claimed "Poin 1 BENARAN BEDA" based on local source code only. Did not verify production deployed state.
2. **Silent deploy failures:** Two consecutive pushes (`0d912ec`, `159ac0b`) both failed at Vercel deploy step. AI did not detect this — assumed success.
3. **Owner discoverable bug:** UI features visible in screenshots but unreachable in production. Owner had to manually verify and report.
4. **No post-deploy verification step:** No automated check that Vercel deployment reached READY state after push.

### Long-term

1. **Separate CI from CD** — CI builds and runs tests. CD uses Vercel Git integration (not CLI), which handles deploys natively and surfaces failures via PR checks.
2. **Add smoke test endpoint** — `/api/healthz` exists for backend. Add `/api/version` returning deployed commit SHA. Frontend can ping and detect stale deploys.

## Lessons Learned

| Lesson | Why it matters |
|---|---|
| **Local typecheck success ≠ production deploy success** | Build can succeed locally but fail to deploy. Always verify post-deploy. |
| **Vercel deploy errors are silent unless checked** | Failed deploys keep previous production live. No alert to developer unless checked. |
| **Owner testing surfaces what automated checks miss** | Owner's screenshot caught the bug that AI's "typecheck passes" did not. |
| **Force push temptation** | Resisted `git reset --hard 9a11a30` + force push. Used `git revert` instead — preserves audit trail. |
| **Untracked files in deploy context are dangerous** | `.vercelignore` was the silent killer. All deploy-affecting files should be git-tracked. |
