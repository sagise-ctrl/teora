# Architecture

## Overall Architecture

```
[React SPA (Vercel)] --> [HTTP / HTTPS] --> [Express API Server (VPS Ubuntu)] --> [PostgreSQL (Supabase)]
                                                                          |
                                                                          v
                                                                   [Supabase Auth]
                                                                   (JWKS validation)
```

## Frontend: academic-workspace

**Location:** `artifacts/academic-workspace/`

- React 19 SPA (single-page application)
- Vite bundler
- Development: port 18543 via `pnpm --filter @workspace/academic-workspace run dev:bypass`
- Production build: outputs to `dist/`, served by Vercel
- Tailwind CSS v4 with CSS-first configuration (theme defined in `index.css` with `@theme` directive)
- TanStack Query for all server state
- wouter for routing
- MSW (Mock Service Worker) for API mocking in development

**API communication:** Calls go to `VITE_API_URL` env var (absolute URL of VPS backend). Vite proxy in `vite.config.ts` only applies in dev mode.

## Backend: api-server

**Location:** `artifacts/api-server/`

- Express 5 on port 8080
- PM2 managed on VPS
- Routes in `src/routes/` (modular: activities, attachments, documents, exports, jobs, metadata, projects, references)
- Zod validation on all inputs via `@workspace/api-zod`
- Drizzle ORM for database access via `@workspace/db`
- pino logger for structured logging
- JWT validation via `jose` library + Supabase JWKS on every `/api/*` request except `/api/auth` and `/api/webhooks`
- Error middleware catches all errors, returns structured `{ error: ... }` responses, never leaks stack traces in production

## Libraries (lib/)

| Library | Purpose |
|---------|---------|
| `api-spec` | OpenAPI YAML spec -- single source of truth for API types |
| `api-zod` | Zod schemas generated from OpenAPI via Orval |
| `api-client-react` | TanStack Query hooks generated by Orval |
| `db` | Drizzle ORM schema (13 tables) |

### Code Generation Pipeline

```
lib/api-spec/openapi.yaml --> Orval --> lib/api-zod/ (Zod schemas)
                                        --> lib/api-client-react/ (TanStack Query hooks)
```

After any OpenAPI schema change:
```bash
pnpm --filter @workspace/api-spec run codegen
```

## Database Schema

PostgreSQL on Supabase. 13 tables:

- `users` -- user profiles
- `projects` -- academic project workspaces
- `documents` -- documents/chapters within projects
- `references` -- bibliographic references
- `attachments` -- uploaded files
- `messages` -- AI chat messages
- `activities` -- project activity log
- `jobs` -- background AI jobs (analyze, write, export)
- `exports` -- export records
- `project_metadata` -- key-value metadata
- `referrals` -- referral tracking
- `referral_events` -- referral event log
- `index` -- (verify exact purpose in schema)

## Authentication Flow

```
1. User signs up / logs in via Supabase Auth (frontend SDK)
2. Supabase issues JWT (access token)
3. Frontend attaches JWT in Authorization: Bearer <token> header
4. Backend validates JWT via jose + Supabase JWKS endpoint
5. User ID extracted from JWT claims for all requests
```

Public endpoints (no JWT required):
- `POST /api/auth/*` -- authentication endpoints
- `POST /api/webhooks/*` -- webhooks

## Key Routing Gotcha

In `src/routes/index.ts`, **always register `/projects/stats` BEFORE `/projects/:projectId`**. Express matches routes in registration order; without this, "stats" gets captured as a `projectId` parameter.

## Environment Variables

### Frontend (Vercel)
- `VITE_API_URL` -- full URL of the VPS backend API (e.g., `https://api.teora.app`)
- `VITE_SUPABASE_URL` -- Supabase project URL
- `VITE_SUPABASE_ANON_KEY` -- Supabase anon key

### Backend (VPS)
- `DATABASE_URL` -- PostgreSQL connection string (Supabase)
- `SUPABASE_JWT_SECRET` -- Supabase JWT secret for validation
- `SUPABASE_JWKS_URI` -- JWKS endpoint for token verification
- `PORT` -- server port (default 8080)
- `AI_*` -- AI provider config (AI_PROVIDER, AI_BASE_URL, AI_API_KEY, AI_MODEL)
