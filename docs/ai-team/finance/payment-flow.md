# Payment Flow - Teora

## Payment Architecture

```
User Browser
    │
    ▼
Frontend (React SPA) ←→ Payment Provider (Stripe)
    │                       │
    ▼                       │ Webhooks
API Server (Express) ──────────────────────► Payment Provider API
    │
    ▼
Supabase DB
    │
    ▼
Token Balance Update
```

## Payment Provider: Stripe

**Dipilih:** Stripe (bukan Povio/Pagar.me/Snapcall)

**Alasan:**
- Mature, well-documented API
- Global coverage (IDR/USD support)
- Subscription management built-in
- Webhook untuk real-time updates
- Clear pricing (2.9% + $0.30 per successful charge)
- Bisa digunakan untuk token top-up (one-time) dan subscription

**Alternatif yang dipertimbangkan:**
- Povio: Lebih murah untuk Indonesia, tapi fitur subscription lebih terbatas
- Pagar.me: Alternatif lokal lain
- Manual transfer: Terlalu manual, tidak scalable

## Two Payment Types

### 1. Recurring Subscription (Monthly)

```
User memilih paket → Stripe Checkout (Subscription mode)
    ↓
User bayar via Stripe
    ↓
Stripe webhook: invoice.payment_succeeded
    ↓
API Server update: subscription_status = active, tokens_balance = tier_limit
    ↓
User mendapat akses
```

**Stripe objects used:**
- Customer (one per user)
- Price (one per tier: price_starter, price_lite, price_academic, price_team)
- Subscription (linked to customer + price)
- Invoice (generated by Stripe per billing period)

### 2. One-time Token Purchase (Pay-per-use)

```
User pilih jumlah token → Stripe Checkout (Payment mode)
    ↓
User bayar via Stripe
    ↓
Stripe webhook: payment_intent.succeeded
    ↓
API Server: tokens_balance += purchased_amount
    ↓
User mendapat token
```

**Stripe objects used:**
- PaymentIntent (one per purchase)
- No subscription (one-off)

## Payment Webhook Flow

Webhook endpoint: `POST /api/webhooks/stripe`

**Supported events:**
1. `checkout.session.completed` — new subscription or purchase
2. `invoice.payment_succeeded` — subscription renewal
3. `invoice.payment_failed` — subscription payment failed
4. `customer.subscription.updated` — tier change, pause
5. `customer.subscription.deleted` — cancellation
6. `payment_intent.succeeded` — one-time purchase

**Webhook security:**
- Verify Stripe signature (webhook secret)
- Idempotency: check if event already processed (store event_id in DB)
- Process asynchronously to avoid timeout

## Subscription Status Transitions

```
None → Active (payment succeeded)
Active → Past Due (payment failed, grace period 7 days)
Past Due → Active (payment retried and succeeded)
Past Due → Cancelled (7 days grace period expired)
Active → Cancelled (user cancelled)
Cancelled → Active (user resubscribed)
```

## Cancellation Flow

```
User clicks Cancel Subscription
    ↓
Stripe: subscription.cancel_at_period_end = true
    ↓
No more charges, access continues until period end
    ↓
At period end: subscription.deleted webhook
    ↓
API Server: subscription_status = cancelled, tokens_balance = 0
    ↓
User downgraded to free tier
```

## Token Deduction Flow

```
User triggers AI feature (analyze, write, chat, export)
    ↓
API Server: check tokens_balance >= estimated_tokens
    ↓
If insufficient:
    → Return 402 Payment Required
    → Frontend shows "Top up tokens" prompt
If sufficient:
    → Proceed with AI request
    ↓
AI request completes
    ↓
API Server: log actual tokens_used
    ↓
API Server: tokens_balance -= actual_tokens_used
    ↓
If tokens_balance < 0 (edge case):
    → Cap at 0
    → Flag account for review
    → Send notification: "You've exceeded your token limit"
```

## Cost Tracking

Setiap AI request harus track cost:

```typescript
interface TokenUsage {
  request_id: string;
  user_id: string;
  project_id: string;
  job_type: 'analyze' | 'write' | 'chat' | 'export' | 'reference';
  model_used: string;
  input_tokens: number;
  output_tokens: number;
  cost_cents: number; // calculated cost in cents
  created_at: Date;
}
```

Cost calculation formula:
```typescript
function calculateCost(inputTokens: number, outputTokens: number, modelTier: 'budget' | 'standard' | 'premium'): number {
  const rates = {
    budget:    { input: 0.15, output: 0.60 },
    standard:  { input: 2.50, output: 10.00 },
    premium:   { input: 3.00, output: 12.00 }
  };
  const rate = rates[modelTier];
  return ((inputTokens / 1000) * rate.input + (outputTokens / 1000) * rate.output) * 100; // in cents
}
```

## Edge Cases

1. **User downgrades tier mid-cycle:**
   - Prorate credit untuk sisa hari
   - Terapkan tier baru
   - Balance disesuaikan

2. **User upgrades tier mid-cycle:**
   - Charge prorated difference
   - Bonus tokens dari upgrade

3. **Token limit reached during active request:**
   - Proses request selesai dulu (avoid half-done state)
   - Deduct tokens
   - Notify user setelah request selesai

4. **Webhook delivery failure:**
   - Stripe retry automatically (up to 72 hours)
   - Idempotency key prevents double-processing
   - Monitor failed webhooks via Stripe dashboard

5. **Negative balance (edge case):**
   - Cap at 0
   - Alert owner
   - Suspend subscription until top-up
