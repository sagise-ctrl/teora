# Project Patterns

Common patterns observed in the Teora codebase.

## 1. Route Handler Pattern (Express)

```typescript
export async function GET(req: Request, { params }: { params: { id: string } }) {
  try {
    const { id } = await z.object({ id: z.string().uuid() }).parseAsync(params);
    const result = await db.select().from(projects).where(eq(projects.id, id));
    return Response.json({ data: result[0] ?? null });
  } catch (error) {
    if (error instanceof z.ZodError) {
      return Response.json({ error: 'Validation error', details: error.errors }, { status: 400 });
    }
    logger.error({ error });
    return Response.json({ error: 'Internal server error' }, { status: 500 });
  }
}
```

Key points:
- Always wrap in try-catch (Express 5 does not auto-catch)
- Validate params/query/body with Zod
- Return structured error responses
- Log errors with pino, never expose internals to client

## 2. TanStack Query Hook Pattern

- Hooks are auto-generated by Orval in `lib/api-client-react/src/generated/`
- Use query keys for invalidation:

```typescript
queryClient.invalidateQueries({ queryKey: ['project', id] });
```

- Use `useMutation` for writes
- Invalidate related queries in `onSuccess`

## 3. Form Pattern (react-hook-form + zod)

1. Define Zod schema for form validation
2. Wrap with `FormProvider`
3. Use `useForm` hook
4. Use `@hookform/resolvers/zod` as resolver
5. Handle submission in `onSubmit`

## 4. Radix UI Component Pattern

- shadcn/ui components built on Radix primitives
- Override with `className` prop
- Compose within `Card` component for consistent styling

## 5. Drizzle ORM Query Pattern

- Always use schema types from `lib/db`
- Prefer prepared statements for repeated queries
- Use transactions for multi-table operations
