## Root Cause (CONFIRMED via runtime error)

tiktoken npm package uses **WASM** (`tiktoken_bg.wasm`) for fast tokenization. esbuild bundles the JS but does NOT bundle the `.wasm` file by default. Vercel's deployment doesn't auto-include `.wasm` from `node_modules`.

Result: At function runtime, tiktoken tries to `require.resolve('tiktoken_bg.wasm')` and fails → process exits with status 1 → all routes 500.

**Class:** Same as **ERR-012** (native dep externalization — link: drizzle-zod), extended to WASM.

## Post-mortem Notes

This incident validates owner's frustration: "ada kendala di error yg berulangan. saya sudah bikin semacem sop dalam penanganan error, harapan saya itu bisa tergunakan."

I followed the SOP but missed a critical verification step (Step 6 VERIFY was bundle-grep only, not runtime smoke test). The fix is to add runtime verification (local import check or `vercel dev` start) for deps with non-JS bindings BEFORE deploying to production.

**Lesson:** "Build succeeded" is necessary but NOT sufficient for production deploys involving deps with native assets (WASM, `.node` binaries, native addons). Always do a runtime smoke test first.

**SOP self-correction (Step 10):** Going forward, deploy-error-protocol Step 6 will require: (a) `node -e "import('./dist/index.mjs')"` smoke test OR `vercel dev` start, (b) curl `/api/healthz` post-deploy, (c) inspect Vercel runtime logs for 5 minutes.
